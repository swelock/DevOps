# Архитектура приложения

## Компоненты

`campus/__init__.py` содержит фабрику Flask, маршруты HTTP API и проверку входных
данных. `campus/database.py` предоставляет общий интерфейс к SQLite и PostgreSQL:
соединение, выполнение запросов и транзакции. ORM не используется.

`campus/templates/index.html` — страница приложения. `campus/static/app.js`
загружает справочники, отправляет запросы и обновляет таблицы; `style.css`
задаёт оформление. Сборка фронтенда не требуется.

`run.py` предназначен для локального запуска. На Linux фабрику `campus:create_app()`
загружает Gunicorn с двумя рабочими процессами. Службой управляет systemd.

## Обработка запроса

При добавлении помещения браузер передаёт JSON в `POST /api/rooms`.
Сервер проверяет поля, типы, диапазоны и ссылки на справочники. Значения SQL
передаются параметрами, имя таблицы выбирается из фиксированного списка ресурсов.
Для PostgreSQL адаптер заменяет плейсхолдеры `?` на `%s`.

Соединение создаётся по необходимости и сохраняется в контексте запроса Flask.
Изменение выполняется в транзакции: при успехе — commit, при исключении — rollback.
Сервер читает созданную запись и добавляет вычисляемый объём. Для площади
40.5 м² и высоты 3.2 м ответ содержит `volume: 129.6`. После запроса соединение
закрывается.

Валидация API возвращает понятные ошибки ввода. Ограничения `UNIQUE`, `CHECK`
и внешние ключи сохраняют целостность на уровне БД. Контракт запросов и ответов
описан в [API.md](API.md).

## Хранение данных

SQLite используется локально и в автоматических тестах. Схема создаётся при
первом запуске без удаления существующих записей. На стенде схема PostgreSQL
создаётся административным скриптом до запуска приложения. Системы миграций нет.

`campus_owner` владеет объектами PostgreSQL и имеет `NOLOGIN`. Прикладная роль
`campus_app` получает подключение, CRUD таблиц и доступ к последовательностям,
но не права владельца. Схемы и ограничения описаны в [DATA.md](DATA.md).

## Размещение и доступ

Браузер обращается к `campus-app` (`172.16.114.10:8000`), приложение — к PostgreSQL
на `campus-db` (`172.16.114.20:5432`). Обе машины находятся в NAT-сети VMware Fusion.
Постоянные адреса задаёт Netplan.

Linux-пользователь `campusapp` запускает службу без интерактивного shell.
Исходники принадлежат root и доступны службе на чтение, но не на запись.
Конфигурация отделена от кода в `/etc/campus/campus.env`.

UFW разрешает SSH из административной сети, HTTP из клиентской сети и PostgreSQL
только с адреса сервера приложения. `pg_hba.conf` дополнительно ограничивает
доступ к БД и требует `scram-sha-256`. Удалённый root-вход и парольный SSH отключены.

## Управление и ограничения

systemd обеспечивает автозапуск, остановку, перезапуск и журналирование.
`Restart=on-failure` восстанавливает службу после аварии с задержкой 3 секунды.
`/health` читает все три таблицы: HTTP 200 подтверждает доступность БД и схемы,
HTTP 503 означает ошибку зависимости. Эта проверка не заменяет тестирование CRUD.

В текущей версии отсутствуют учётные записи пользователей приложения,
разграничение ролей, HTTPS, пагинация, контейнеры и CI/CD. Доступ ограничен
внутренней сетью. Команды управления собраны в [OPERATIONS.md](OPERATIONS.md).
