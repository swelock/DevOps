# Развёртывание лабораторной работы 2

Это инструкция для двух чистых Ubuntu Server 24.04 без Docker. Итоговый стенд:

| Узел | Имя | Постоянный адрес | Открытые входящие порты |
|---|---|---:|---|
| приложение | `campus-app` | `192.168.56.10/24` | 22 из сети администрирования, 8000 из клиентской сети |
| база данных | `campus-db` | `192.168.56.20/24` | 22 из сети администрирования, 5432 только от `192.168.56.10` |

У каждой VM удобно иметь два адаптера: NAT для установки пакетов и Host-only
для закрытой сети стенда. Адреса Host-only не должны пересекаться с другой сетью
вашего компьютера.

## 1 Создание машин и постоянные адреса

Создайте две VM с Ubuntu Server 24.04, минимум 1 CPU, 1 ГиБ RAM и 10 ГиБ диска.
Задайте имена:

```bash
sudo hostnamectl set-hostname campus-app  # первая VM
sudo hostnamectl set-hostname campus-db   # вторая VM
```

На каждой VM выполните `ip -br link`, замените имена интерфейсов в подходящем
файле из `deploy/netplan`, скопируйте его в `/etc/netplan/01-campus.yaml` с
правами `0600`, затем примените:

```bash
sudo netplan try
sudo netplan apply
ip -br address
ping -c 2 192.168.56.20  # с campus-app
ping -c 2 192.168.56.10  # с campus-db
```

`netplan try` автоматически откатит ошибочную сетевую конфигурацию, если её не
подтвердить. Не закрывайте консоль VM до проверки SSH.

## 2 SSH и пользователи

Создайте ключ на компьютере администратора, если его ещё нет:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/campus_lab
```

Передайте репозиторий и только открытый файл `campus_lab.pub` на обе VM. На каждой
машине из консоли выполните:

```bash
cd /путь/к/Project_DevOps
sudo deploy/scripts/bootstrap-common.sh /путь/к/campus_lab.pub
```

Сначала проверьте новую SSH-сессию `ssh -i ~/.ssh/campus_lab
devopsadmin@192.168.56.10` (затем `.20`) и лишь потом закрывайте старую.
Скрипт создаёт `devopsadmin`, добавляет его в `sudo`, устанавливает ключ и запрещает
root/password login. Пользователь службы `campusapp` создаётся следующим скриптом
без интерактивного shell.

## 3 Сервер PostgreSQL

На `campus-db`:

```bash
cd /путь/к/Project_DevOps
sudo deploy/scripts/setup-db-server.sh 192.168.56.10 192.168.56.20 192.168.56.0/24
```

Введите новый пароль длиной не менее 16 символов. Разрешены буквы, цифры, `_` и
`-`; это исключает неоднозначный разбор `EnvironmentFile`. Скрипт установит
PostgreSQL, создаст БД, роли, таблицы, `pg_hba.conf` и UFW. `campus_owner` не может
войти в систему и владеет объектами; `campus_app` может подключаться и выполнять
только CRUD над данными и использовать последовательности.

## 4 Сервер приложения

На `campus-app` с той же версией репозитория:

```bash
cd /путь/к/Project_DevOps
sudo deploy/scripts/setup-app-server.sh 192.168.56.20 192.168.56.0/24 192.168.56.0/24
```

Введите тот же пароль. Скрипт установит Python/Gunicorn, скопирует приложение в
`/opt/campus/app`, создаст закрытый `/etc/campus/campus.env`, установит и запустит
`campus.service`, затем настроит UFW. Исходники доступны на чтение группе службы,
но изменяются только root; пароль доступен root и группе `campusapp`.

Откройте `http://192.168.56.10:8000`. Повторное развёртывание выполняется той же
командой; после обновления кода перезапустите службу:

```bash
sudo systemctl restart campus
```

## 5 Проверка

```bash
# campus-app
sudo /opt/campus/app/deploy/scripts/verify-host.sh app

# campus-db, из рабочего клона
sudo deploy/scripts/verify-host.sh db
```

Полный сценарий живой защиты, включая перезагрузку, отказ БД, поиск процесса,
порта и журналов, контрольное изменение службы и отрицательную сетевую проверку,
находится в `docs/LR2-CHECKLIST.md`.

## Ограничения безопасности

- не добавляйте `/etc/campus/campus.env`, приватные SSH-ключи или дампы БД в Git;
- не запускайте Gunicorn вручную через `sudo`; единственная штатная точка запуска —
  `systemctl`;
- не добавляйте общее правило UFW для 5432;
- перед отключением парольного SSH обязательно подтвердите вход по ключу;
- скрипты рассчитаны на свежие учебные VM: существующие посторонние правила UFW
  они не удаляют, их отсутствие нужно проверить вручную.
